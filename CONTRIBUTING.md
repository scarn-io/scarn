# Contributing

Thanks for helping out. Bug reports, feature requests and pull requests are
all welcome.

## How this repository works

This repository is a mirror. Scarn is developed in a private monorepo, and the
open-source parts are synced here from it. That means:

- Pull requests are reviewed here as usual, but they are not merged here.
  Once a PR is approved, a maintainer ports the change to the private repo,
  with you credited as an author through a `Co-authored-by:` trailer. The
  change then comes back to this repository with the next sync, and the PR is
  closed with a link to it.
- Some files are generated by the sync, notably the root `package.json` and
  `bun.lock`. Change workspace `package.json` files rather than the root one.
- For anything larger than a small fix, open an issue first so we can agree
  on the approach before you write code.

## Setup

You need [Bun](https://bun.sh) (the version is pinned in the root
`package.json` under `packageManager`) and Docker, for Postgres and the
integration tests. The repository also ships a devcontainer
(`.devcontainer/`) with everything installed.

```sh
bun install
```

## Checks

Run these from the repo root before opening a PR:

```sh
bun run typecheck
bun run test:unit
```

`test:unit` runs the unit tests of `packages/core` and `apps/api`. Integration
tests start Postgres with testcontainers, so they need Docker. Run them per
workspace:

```sh
cd packages/core && bun run test
```

### Lint

`bun run lint` lints the whole repository in one ESLint process and can run
out of memory. Lint the workspaces you changed instead:

```sh
bunx eslint packages/core
bunx eslint apps/api
```

Format only the files you touched (`bunx prettier --write <paths>`), not the
whole repository.

## Running the server locally

The server needs Postgres with the [pgvector](https://github.com/pgvector/pgvector)
extension. One way to get it:

```sh
docker run -d --name scarn-db -p 6429:5432 \
  -e POSTGRES_DB=scarn -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres \
  pgvector/pgvector:pg17
```

Then apply the migrations. `db:migrate` reads `DATABASE_URL` from the
environment or from a `.env` file in the repo root:

```sh
echo 'DATABASE_URL=postgres://postgres:postgres@localhost:6429/scarn' >> .env
bun run db:migrate
```

To run the full server the way users do, see the
[self-hosting quickstart](https://scarn-io.github.io/scarn/self-hosting/quickstart/),
which uses `docker-compose.selfhost.yml` and `.env.selfhost.example`.
